# AI Prospecting (v0.4.0)

Prospecting lets a workspace collect businesses it might reach out to — and
qualify them with explainable, rule-based scoring. This document states
plainly what works, what is blocked, and what is never done.

## The honesty rule (non-negotiable)

**FlowPilot never invents prospect data.** No email, phone number, revenue
figure, employee count, or company fact is ever generated by the system.
Every prospect field comes from one of three places:

1. **User input** — the manual-add form (`POST /api/prospects`, `sourceType: "manual"`).
2. **An import** — a bulk import flow (`sourceType: "import"`).
3. **A real provider response** — a configured search/business-data provider,
   with the provider's source link stored as `sourceUrl` (`sourceType: "search"`).

A prospect with no `sourceUrl` is **unverified — user-entered**. The UI shows
that label, and the API exposes it as `verified: false`. Treat unverified
records as leads to verify, not as facts.

## Search flow

1. The user submits a search: industry (required), country, region, business
   type, ICP fields, keywords, exclusions, target count (1–500, default 25).
   Route: `POST /api/prospects/searches` (MANAGER+).
2. The server calls `searchProspects()` in `src/lib/prospecting/providers.ts`,
   which consults the provider registry.
3. The search row is saved with its outcome, and past searches are listed
   at `GET /api/prospects/searches`.

### The blocked-provider state (v0.4.0)

**No search/business-data provider is configured in v0.4.0.** The registry
in `src/lib/prospecting/providers.ts` is intentionally empty, and every
search attempt returns:

```json
{
  "blocked": true,
  "code": "SEARCH_PROVIDER_NOT_CONFIGURED",
  "prerequisite": "Configure a search/business-data provider (env SEARCH_PROVIDER + its API key; see docs/PROSPECTING.md) — no provider is configured in v0.4.0"
}
```

The search row is stored with `status: "BLOCKED_NO_SOURCE"` and the
prerequisite in its `error` field. **No prospects are created and no results
are fabricated** to fill the gap. The UI shows the blocked state and the
prerequisite verbatim.

### Adding a provider (future work)

A future provider integration must:

- Implement the `SearchProvider` interface (`search(params)` returning
  prospects **with a `sourceUrl` for every record**).
- Register itself in `SEARCH_PROVIDERS` and report `configured: true` only
  when `SEARCH_PROVIDER` selects it **and** its API key is present.
- Be documented here, including what data it returns and its terms of use
  (notably: only use business data you are licensed to use, and respect the
  provider's rules on storage and outreach).

Until then, `SEARCH_PROVIDER` is not a recognized env var anywhere in the
codebase — setting it does nothing, by design.

## Qualification criteria

Scoring is rule-based and deterministic — no AI calls. It lives in
`src/lib/prospecting/qualify.ts` (`scoreProspect(prospect, criteria)`), and
the same prospect + criteria always produce the same score and reasons.

Criteria format (JSON, supplied on prospect create as `criteria`):

```json
{
  "requiredFields": ["email", "website"],
  "keywordBonuses": { "emergency": 20, "residential": 10 },
  "regionMatches": ["Cairo", "Giza"],
  "industryMatches": ["Plumbing"]
}
```

- `requiredFields`: each present field earns **+10**; each missing field
  earns 0 and is named in the reasons (e.g. `missing website (+0)`).
  Recognized fields: `businessName`, `industry`, `website`, `email`,
  `phone`, `country`, `region`, `description`, `sourceUrl`. Unknown fields
  are ignored with a reason, never scored.
- `keywordBonuses`: keyword → points, matched case-insensitively against
  the business name, industry, and description.
- `regionMatches` / `industryMatches`: a case-insensitive exact match earns
  **+15** each; a non-match is named in the reasons.
- Scores are capped at 100 and floored at 0. With no criteria, the score is
  0 with the reason "no qualification criteria supplied".

The API stores `qualificationScore` and `qualificationReasons` (JSON array)
on the prospect; the UI displays both, so any score can be audited.

## Dedupe rules

Defined in `src/lib/prospecting/dedupe.ts` and enforced on prospect create
and on PATCH when identity fields change:

- **Same normalized domain** → duplicate, regardless of name or country.
  `normalizeDomain` lowercases, strips the scheme, strips a leading `www.`,
  drops path/query/fragment, and strips a trailing dot.
  (`https://WWW.Acme.example/about` ≡ `acme.example`)
- **Same normalized name + same country** → duplicate.
  `normalizeName` lowercases, strips punctuation, drops trailing legal
  suffixes (`Inc`, `LLC`, `Ltd`, `Corp`, `Co`, `GmbH`, …), and collapses
  whitespace. (`"Acme, Inc."` ≡ `"ACME LLC"`; country compared
  case-insensitively, and both sides must have a country.)
- Anything else is not a duplicate: same name in a different country, or
  same country with a different name and no website, are distinct records.

A duplicate create/PATCH returns **409** with code `DUPLICATE_PROSPECT` and
`existingId` (plus `existingIds`). Dedupe never merges silently — the user
decides what to do with the existing record.

## Export

`GET /api/prospects/export` (MANAGER+) returns all workspace prospects as
CSV, ordered newest first. **Formula-injection neutralization:** any cell
whose raw value starts with `=`, `+`, `-`, `@`, `|`, or `%` is prefixed
with a single quote (`'`) before CSV quoting, so a spreadsheet never
executes user-entered content as a formula.

## API summary

| Route | Access | Purpose |
|---|---|---|
| `GET /api/prospects` | Member | List + filters (`status`, `industry`, `country`, `search`, `minScore`) |
| `POST /api/prospects` | AGENT+ | Manual create; 409 on duplicate |
| `GET/PATCH/DELETE /api/prospects/[id]` | Member / AGENT+ / AGENT+ | Detail, update (dedupe re-checked), delete |
| `GET /api/prospects/searches` | Member | List searches |
| `POST /api/prospects/searches` | MANAGER+ | Create search → `BLOCKED_NO_SOURCE` in v0.4.0 |
| `GET /api/prospects/export` | MANAGER+ | CSV export, formula-neutralized |
| `GET /api/sms/status` | Member | SMS provider status (see below) |

## Related: SMS and LinkedIn

- **SMS:** no SMS provider is configured in v0.4.0 (`src/lib/sms/providers.ts`
  registry is empty; `GET /api/sms/status` returns `configured: false` with
  code `SMS_PROVIDER_NOT_CONFIGURED`). There is no `sms` campaign channel
  and SMS sends are never simulated.
- **LinkedIn:** see `docs/LINKEDIN_STATUS.md`. LinkedIn automation
  (messaging, connection requests, prospect extraction via the official API)
  is unsupported and not built.
